# HurshNote 实施计划

> 目标：做一个在日常编辑上不输 Notepad++、在大文件、可靠性和开发者工具上全面超过它的 Windows 文本编辑器。
> 需求见 [REQUIREMENTS.md](REQUIREMENTS.md)，设计见 [ARCHITECTURE.md](ARCHITECTURE.md)，坑见 [PITFALLS.md](PITFALLS.md)。

## 已确认的决策

| 项 | 决策 |
|---|---|
| 语言 | Rust（stable，MSVC 工具链） |
| 界面 | 原生 Win32（`windows` crate），不使用 GUI 框架和浏览器内核 |
| 编辑内核 | Scintilla 5 + Lexilla，静态编译进 exe |
| 大文件 | 双层模式；超过 256 MB 进入只读大文件视图（搜索、跳转、Hex、Tail） |
| Markdown | `pulldown-cmark` 解析 + Direct2D/DirectWrite 原生自绘，分栏预览 |
| 加密 | 密码派生：Argon2id + AES-256-GCM |
| 平台 | 仅 Windows 10 1809+ x64 |
| 分发 | 便携 zip + Inno Setup 安装包，不做代码签名 |
| 协议 | MIT；禁止复制 Notepad++（GPL）代码 |

## 开发方式

- 代码在 GitHub 上维护；每次推送由 GitHub Actions（`windows-latest`）编译、测试并上传 exe 产物，在 Windows 电脑上下载试用。
- 云端 Linux 环境可跑跨平台 crate 的测试，并用 `cargo-xwin` 交叉编译检查 Windows 部分能否通过编译；界面行为以 Windows 上实测为准。
- 每个里程碑结束时：跑一遍性能预算（ARCHITECTURE §7），更新本文件的勾选状态。

- [x] "重新打开为"（重新解码磁盘字节）/"转换为"（改变保存编码）

- [x] 无级缩放（Ctrl+滚轮 ×1.1、Ctrl+= / Ctrl+- / Ctrl+0，小键盘同样可用）

- [x] 列表续写（Markdown/纯文本）与自动缩进（所有语言）
- [x] 行操作：排序（升/降/忽略大小写/数值）、去重（全部/相邻）、删除行首/行尾空白、合并行、删除空行、移动行、复制行、大小写
- [x] 书签：书签栏点击、Ctrl+F2、F2/Shift+F2 循环跳转、复制/剪切/删除带书签行、删除未标记行、反转

- [x] 多文档基础管理（"窗口"菜单列表、Ctrl+Tab 循环、关闭/全部关闭/全部保存）；打开文件时替换空白的未命名文档

**验收：** 语料逐一解码再编码字节级一致（`hn-text` 测试）✅；CI 自测覆盖行操作、列表续写、书签、查找替换、多文档、缩放 ✅；常用操作对照 N++ 无缺失（待真机确认）。

**与原计划的差异：**
- 查找只做了对话框，没有单独的查找栏（对话框是非模态的，可以一直开着）。
- 设置暂存为 `settings.ini`（`键=值`），M3 换成 TOML。
- 编辑区内的文字拖放（拖动选中文字移动）暂不可用：Scintilla 的 OLE 拖放目标不接受文件，为了支持拖入文件，暂未初始化 OLE。M3 用自写的 IDropTarget 同时支持两者。

## M2 可靠性 ✅

**目标：任何时候强杀进程都不丢数据，任何保存都不损坏文件。**

- [x] 安全保存：同目录临时文件 + FlushFileBuffers + ReplaceFileW；符号链接保存到目标；硬链接、替换失败时退化为"备份 + 原地写"
- [x] 只读属性（询问后去掉）、无权限时提权保存（`--elevated-save`，UAC）
- [x] 快照：内容变化后防抖 1.5 s（连续编辑最长 10 s）、切换文档与退出时立即写；独立写入线程，先快照后清单，旧快照在清单写出后删除
- [x] 会话恢复：懒加载（只载入当前文档）、恢复光标/滚动/折叠/书签/只读/换行符/语言、关闭期间磁盘文件被修改时询问保留哪个版本
- [x] 快照模式下关闭不询问保存（文件 > 设置 中可关闭，关闭后恢复传统询问）
- [x] 文件监控：后台线程每秒轮询修改时间与大小，UI 线程再比较内容哈希；自己保存不误报；未修改的文档自动重新载入（可关），有修改时询问；删除检测；窗口不在前台时延后到激活再提示
- [x] 崩溃处理：未处理异常写 `MiniDumpNormal`（`%LOCALAPPDATA%\HurshNote\crash`），运行标记检测异常退出并提示已恢复
- [x] `hn-crypto`：加密格式 v1 + 单元测试 + 变异测试（500 次随机篡改均被拒绝）
- [x] 加密文档：打开 `.hne`/任何带魔数的文件时询问密码、另存为加密文件、保存时重新加密；快照用文档密钥加密，恢复时询问密码
- [x] 强杀测试接入 CI（每次构建 20 轮"写入 → 强杀 → 恢复检查"）

**验收：** 强杀测试 20/20 ✅（计划为 500 轮，CI 时间有限先跑 20 轮，可在本地加大）；`fsio` 单元测试覆盖新建、覆盖、硬链接保留、只读属性 ✅；自测覆盖安全保存与加密往返（并确认密文中没有明文）✅。

**与原计划的差异：**
- 文件监控用轮询代替 ReadDirectoryChangesW（理由见 ARCHITECTURE §6.7）。
- 撤销历史仍不持久化：恢复后的文档以快照内容为起点，无法撤销到关闭前。
- "保存过程中断电"的故障注入测试未做，依赖 ReplaceFileW 的原子性。
- 加密的"修改密码"放到 M6。
