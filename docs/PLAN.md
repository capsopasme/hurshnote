# HurshNote 实施计划

> 目标：做一个在日常编辑上不输 Notepad++、在大文件、可靠性和开发者工具上全面超过它的 Windows 文本编辑器。
> 需求见 [REQUIREMENTS.md](REQUIREMENTS.md)，设计见 [ARCHITECTURE.md](ARCHITECTURE.md)，坑见 [PITFALLS.md](PITFALLS.md)。

## 已确认的决策

| 项 | 决策 |
|---|---|
| 语言 | Rust（stable，MSVC 工具链） |
| 界面 | 原生 Win32（`windows` crate），不使用 GUI 框架和浏览器内核 |
| 编辑内核 | Scintilla 5 + Lexilla，静态编译进 exe |
| 大文件 | 双层模式；超过 256 MB 进入只读大文件视图（搜索、跳转、Hex、Tail） |
| Markdown | `pulldown-cmark` 解析 + Direct2D/DirectWrite 原生自绘，分栏预览 |
| 加密 | 密码派生：Argon2id + AES-256-GCM |
| 平台 | 仅 Windows 10 1809+ x64 |
| 分发 | 便携 zip + Inno Setup 安装包，不做代码签名 |
| 协议 | MIT；禁止复制 Notepad++（GPL）代码 |

## 开发方式

- 代码在 GitHub 上维护；每次推送由 GitHub Actions（`windows-latest`）编译、测试并上传 exe 产物，在 Windows 电脑上下载试用。
- 云端 Linux 环境可跑跨平台 crate 的测试，并用 `cargo-xwin` 交叉编译检查 Windows 部分能否通过编译；界面行为以 Windows 上实测为准。
- 每个里程碑结束时：跑一遍性能预算（ARCHITECTURE §7），更新本文件的勾选状态。

## M2 可靠性 ✅

**目标：任何时候强杀进程都不丢数据，任何保存都不损坏文件。**

- [x] 安全保存：同目录临时文件 + FlushFileBuffers + ReplaceFileW；符号链接保存到目标；硬链接、替换失败时退化为"备份 + 原地写"
- [x] 只读属性（询问后去掉）、无权限时提权保存（`--elevated-save`，UAC）
- [x] 快照：内容变化后防抖 1.5 s（连续编辑最长 10 s）、切换文档与退出时立即写；独立写入线程，先快照后清单，旧快照在清单写出后删除
- [x] 会话恢复：懒加载（只载入当前文档）、恢复光标/滚动/折叠/书签/只读/换行符/语言、关闭期间磁盘文件被修改时询问保留哪个版本
- [x] 快照模式下关闭不询问保存（文件 > 设置 中可关闭，关闭后恢复传统询问）
- [x] 文件监控：后台线程每秒轮询修改时间与大小，UI 线程再比较内容哈希；自己保存不误报；未修改的文档自动重新载入（可关），有修改时询问；删除检测；窗口不在前台时延后到激活再提示
- [x] 崩溃处理：未处理异常写 `MiniDumpNormal`（`%LOCALAPPDATA%\HurshNote\crash`），运行标记检测异常退出并提示已恢复
- [x] `hn-crypto`：加密格式 v1 + 单元测试 + 变异测试（500 次随机篡改均被拒绝）
- [x] 加密文档：打开 `.hne`/任何带魔数的文件时询问密码、另存为加密文件、保存时重新加密；快照用文档密钥加密，恢复时询问密码
- [x] 强杀测试接入 CI（每次构建 20 轮"写入 → 强杀 → 恢复检查"）

**验收：** 强杀测试 20/20 ✅（计划为 500 轮，CI 时间有限先跑 20 轮，可在本地加大）；`fsio` 单元测试覆盖新建、覆盖、硬链接保留、只读属性 ✅；自测覆盖安全保存与加密往返（并确认密文中没有明文）✅。

**与原计划的差异：**
- 文件监控用轮询代替 ReadDirectoryChangesW（理由见 ARCHITECTURE §6.7）。
- 撤销历史仍不持久化：恢复后的文档以快照内容为起点，无法撤销到关闭前。
- "保存过程中断电"的故障注入测试未做，依赖 ReplaceFileW 的原子性。
- 加密的"修改密码"放到 M6。

## M4 大文件 ✅

**目标：GB 级文件秒开。**

- [x] `hn-large`：分块定位读 + 64 KiB 块缓存（不用 mmap，见下）、稀疏行索引后台构建（每 64 KiB 一项，后台 I/O 优先级）、显示行导航（超长行按 2 KB 网格折行）
- [x] `hn-render` 共享渲染设施（Direct2D/DirectWrite：渲染目标、统一行距的字体、单行排版与命中测试）
- [x] 大文件视图：虚拟滚动（字节比例滚动条）、行号、跳转到行、键盘/鼠标选中与复制（双击选词、拖动自动滚动）、"重新打开为"切换编码、超过 256 MB 自动进入、会话中记住模式与位置
- [x] 大文件流式搜索：查找下一个/上一个（可绕回）、计数、标记全部 → 底部搜索结果面板（F7），点击跳转，Esc 取消
- [x] Hex 视图（`ByteSource` 两种实现：磁盘文件、编辑中文档的编码快照），Ctrl+Shift+H 与文本视图切换并保持位置
- [x] Tail 模式：每 0.5 秒轮询（文件标识 + 长度 + 末尾哈希），增长时续建索引并跟到末尾，截断/轮转/改写时重新读取；普通文档也可开启
- [x] 二进制文件检测与提示（是：Hex 打开；否：按文本打开）

**验收：** 5 GB 日志（CI，`--selftest-large`）首屏 37–250 ms（四次运行，多数约 40 ms；其中渲染目标创建约 3 ms、字体约 0.5 ms）、跳到中间约 4 ms、连续翻页平均约 4 ms / 最慢 5–20 ms、后台建完 4594 万行索引约 3 s ✅；Tail 自测中"改名后新建"式轮转成功（证明不占用文件），轮转后自动从新文件重新读取 ✅；自测覆盖行索引、跳转、绘制、键盘、查找全部/下一个/上一个、复制、Hex 切换、普通文档的 Hex 快照、Tail 增长与轮转、二进制检测 ✅。

**与原计划的差异：**
- 不用内存映射 + SEH：映射会阻止日志轮转、截断后访问映射页会崩溃、网络盘上不可靠；改为每次"打开 → 定位读 → 关闭"并缓存最近 8 MiB，实测性能满足预算（理由见 ARCHITECTURE §6.4）。因此也不需要 C 写的 SEH 包装。
- 超长行不是截断显示，而是在 2 KB 网格点处折成多个显示行，可以完整查看、选中。
- 搜索结果暂时放在主窗口底部的独立面板，M5 的底部抽屉会接管（已在 M5 并入）。
- 大文件搜索按块匹配，跨块边界的跨行匹配不保证；Hex 视图只读（覆盖编辑在 v1 之后）。
- 5 GB 首屏耗时在 CI 上测量，测试文件生成后先 fsync（避免与系统后台写回争抢磁盘），数据可能仍在系统缓存中；真机冷读待确认。

**目标：常见开发辅助不离开编辑器。**

- [x] 目录搜索：对话框（Ctrl+Shift+F；目录、文件类型、排除、大小写/全词/正则/.gitignore/隐藏文件）、后台并行搜索分批回传、虚拟列表（文件行 + 匹配行）、双击跳转并选中匹配、停止
- [x] 目录替换：先搜索预览，确认后替换；已打开的文件在缓冲区替换（可撤销），其余按原编码（含 BOM）走安全保存写回，有损或无法表示的文件跳过并列出原因
- [x] Python 运行：解释器探测（设置 → venv → py 启动器 → PATH，排除商店占位程序）、Job Object、实时输出（stderr 红色、ANSI 颜色）、Traceback 双击跳转、停止（Shift+F5）、在终端中运行（Ctrl+F5）
- [x] 终端：`alacritty_terminal`（ConPTY + VT 状态机）、D2D 网格渲染（粗体/斜体/下划线、宽字符、光标形状）、IME、复制粘贴（含括号粘贴）、resize、多个终端实例、shell 选择（PowerShell / pwsh / cmd / 自定义路径）
- [x] 随附版 ConPTY：alacritty 在 exe 同目录（或 PATH）有 `conpty.dll` + `OpenConsole.exe` 时自动优先加载，否则用系统 ConPTY；是否随发布包附带在 M7 打包时决定

**验收：** 目录搜索（CI，cargo 注册表源码约 5500 个文件、27 万处匹配，热缓存，与 `rg -c` 对比）：首版是 ripgrep 的 1.41 倍；改用目录项自带的文件大小（每个文件少一次打开）、memchr 统计行号后两次运行分别为 1.16 倍、0.96 倍（CI 机器波动较大，ripgrep 自身三次运行相差可达 40%）✅；终端自测：cmd 执行与退出、PowerShell 中 PSReadLine Tab 补全、`Write-Host -ForegroundColor Red` 彩色输出、中文输入回显均通过 ✅；Python 自测：输出、stderr、Traceback、退出码与双击跳转 ✅；目录替换自测：已打开文件在缓冲区替换、GBK 文件按 GBK 写回 ✅。vim 与输入法候选窗位置需要在真机上确认。

**与原计划的差异：**
- 终端没有自己写 ConPTY 封装和 VT 解析，直接用 `alacritty_terminal`（Apache-2.0，与 MIT 兼容；M7 写进 THIRD_PARTY_NOTICES），它同时提供 Windows ConPTY 与随附版 ConPTY 的加载。
- 目录搜索没有用 `grep-searcher`，而是逐文件嗅探编码、解码为 UTF-8 后用 PCRE2（与编辑器内查找同一引擎），这样 GBK/UTF-16 文件也能搜，结果列号与编辑器一致。
- 搜索结果是带"文件行"的平铺虚拟列表，不是可折叠的树。
- 终端暂不向程序报告鼠标事件（vim `mouse=a` 不可用），全屏程序中滚轮转成方向键；多行粘贴不做提示（括号粘贴模式由 shell 自己处理）。
- 输出面板不支持 `input()`（stdin 为空），需要交互时用"在终端中运行"。

**与原计划的差异：**
- 预览默认打开；分屏时焦点视图不是 Markdown 而另一视图是，预览显示另一视图的文档。
- "块树"实现为扁平块列表：嵌套展开为列表层数、引用层数与列表标记，绘制时不再递归。
- 选择超出原计划的"按块选择"：文字块按字符选择，表格、图片、分隔线按整块。
- 增加了渐进排版（原计划未提）：长文档首次排版不阻塞界面。
- 代码块不做语法高亮；远程图片不加载（显示替代文字）；不支持数学公式。
- 宏只保留最近录制的一个，不支持命名多个宏和给宏分配快捷键。
- 打印没有"页面设置"（页边距固定 15 mm），也没有打印预览。
- 修改密码时 KDF 参数同时升级为当前默认值。
